# Trademark Policy

**Draft — pending legal review.** Last updated 2026-11-27.

This policy explains how you can use the names of the Déjà project. It is meant to be short and permissive: we want people to build on Déjà, and we want users to know which software is the real thing.

## The code is Apache-2.0

The Déjà source code is licensed under the [Apache License 2.0](LICENSE). You may use, copy, modify, fork and redistribute the code under that license. Section 6 of the license does not grant permission to use the owner's names or marks, except as needed to describe where the code came from. This policy never limits that use, and it does not restrict any other right the license gives you in the code.

## Things you can do without asking

- **Say what your software does with Déjà.** You may use the name accurately to describe a relationship, for example "works with Déjà", "built on Déjà", "compatible with Déjà" or "a fork of Déjà". Use the name only as much as needed, in plain text, and do not suggest endorsement.
- **Write about Déjà.** Articles, talks, tutorials, reviews and comparisons may use the name.
- **Redistribute unmodified copies** under the original name, with the license and notices intact.
- **Refer to the official repository and packages** by their real names and links.
- **Call yourself a Déjà contributor** if you have contributed to the project. Contributing does not grant any trademark rights.

## Forks and modified versions

You are free to fork Déjà. If you distribute or offer a modified version to others:

- Give it a **different name** that does not include "Déjà" or "deja-run" and is not confusingly similar to them.
- You may say it is "a fork of Déjà" or "based on Déjà", as long as it is clear your project is separate and not official.
- Keep the copyright and license notices Apache-2.0 requires, and state your changes as the license requires.
- Do not use any mark in a way that suggests your fork is the official project.

Private or internal builds do not need to be renamed. Clearly labeled minor patches, such as a distribution's security fixes, may keep the original name.

## Hosted services and products

You may run Déjà yourself and offer services built on it. You may not:

- Name a hosted service, product, company or app "Déjà" or "deja-run", or something confusingly similar.
- Imply that your service is the official, endorsed or sponsored Déjà service, or that it is operated by the owner.
- Register domain names or social media handles that use the names in a way likely to mislead people about who runs them.

An accurate statement such as "powered by Déjà" or "runs Déjà" is fine.

## Package names

- Do not publish packages under the `@deja-run` npm scope unless the owner has authorized it.
- Do not publish packages, on npm or any other registry, with names that imply they are official or maintained by the owner, such as `deja-run-official` or `@deja-run/anything`.
- Using the common word "deja" in an unrelated package name is fine. A package that integrates with Déjà may say so in its description, for example "plugin for Déjà", as long as it does not look official.

## Logo use

Do not use or alter the logo without permission, except to refer to the project in the nominative ways described above, such as a link back to the repository.

## Asking for permission

If you want to use the name as part of your product's name or branding, or do anything else this policy does not clearly allow, open an issue at <https://github.com/deja-run/deja/issues> describing what you would like to do. Please do not assume permission before you hear back.

## Reporting misuse

If you see a use of the Déjà name that looks misleading, open a GitHub issue at the same address.
