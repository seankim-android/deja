## Extra iOS facts (process transport, Maestro 2.12.0)

Load average at the end of this run: 128 / 180 / 235.

1. **Looping animations.** `waitForAnimationToEnd` on Today finished every time (3 of 3): 23.6, 25.4, 20.8 s, against 27.4, 28.9, 21.0 s for a plain `assertVisible` (one process start each). The two are within noise of each other, so the settle itself added no measurable time here and the Blankie idle animation did not block it. Through the process transport the process start hides any small difference; not measured on the MCP transport.

2. **Roles and traits.** Not given. Every hierarchy node has only `accessibilityText`, `title`, `value`, `text`, `hintText`, `resource-id`, `bounds`, `enabled`, `focused`, `selected`, `checked`. There is no element class, role or trait, and no "hittable" flag. `enabled`, `focused`, `selected` and `checked` are present. The driver derives `role` from ID shape only and marks anything it cannot tell as `other`.

3. **Duplicate IDs and selectors.** On fresh Today, 68 nodes had an ID and 60 IDs were distinct. Duplicated: `calendar.pages` x6, `reveal.note.field` x2, `reveal.note.photo` x2, `Toolbar` x2. `id:` is a regular expression matched against the whole ID. `screen.tod.y` matched `screen.today` (the dot is a wildcard), `scr.*` matched, the partial `screen` did not match, and the escaped form `screen\.today` matched. A generated selector must escape regex characters.

4. **System alerts and permission sheets.** The share sheet appears in the hierarchy (`ActivityListView`, see the walks). A SpringBoard permission sheet is not measured: Blankaday in `uiTesting` mode shows none. The in-app alert check was not conclusive (`export.emptyOK` was not found, so that route probably did not reach the alert); not measured.

5. **Crash.** Not measured conclusively. SIGSEGV was sent to the app process in the dedicated simulator, but the hierarchy afterwards still held the app's IDs ({"ok":true,"ids":68,"hasToday":true}), so either the process was restarted before the read or the signal did not end it. After the signal, a tap on `tab.feed` passed. (In this run the assert ran after that tap, so its result says nothing; the order is fixed in `facts.ts` but not re-run.) Maestro printed no crash-specific message that the driver could read. DEJA-7 keeps the "explicit crash signal only" rule; no crash signal is available from Maestro output here.

6. **Dismissing the keyboard.** `pressKey_Enter`: step passed in 21.0 s (load 363), keyboard gone afterwards; `hideKeyboard`: step FAILED in 29.4 s (load 342), keyboard still up afterwards; `tap_outside`: step passed in 17.4 s (load 482), keyboard still up afterwards. Only `pressKey: Enter` closed it on the Today answer field.
